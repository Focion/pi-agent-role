## 目标与授权边界

**目标是完善并首次发布当前 `@pi/agent-role@0.1.0`，不是升级到1.0.0。** 发布形态为内部私有npm、单进程完整核心版，提供可迁移的旧数据、可复查的角色差异性证据及受控安装说明。

本计划承接 [gap计划](2026-10-09-implementation-gap-closure-plan.md) 的 **R01–R39、D01–D02、U01–U03及补充关闭标准**，不替代其逐项证据。7项可选增强O01–O07全部后置。回放、比较属于必需核心，不借“可选增强”名义移出此次范围。

**本轮只新增本计划**。未实施、未改旧文档、源码、schema、包配置或锁文件；未安装依赖、运行测试、构建、打包或发布，未访问上游仓库和registry。所有WP工作包均为todo。以下默认值、目标文件和验收是未来实施契约，不是已经存在或已经验证的能力。

## 基线与方案选择

基线提交为`201b6c8`。本次新增前已有根`AGENTS.md`和gap计划两个未跟踪文件，均保留。当前包版本0.1.0，`package.json:31–34`明确同级mesh依赖；`migrations/001_init.sql`为14领域表，`src/db/db.ts:19`的schema版本为1。既有声明为ESM/CJS/类型三出口（`package.json:13–18`、`tsup.config.ts:3–12`），不代表消费端验证通过。

可以复用SQLite/FTS、身份和策略编译、DAO、记忆打分、部分工具及观测等实现。主要改造是装配和状态闭环，而不是推倒重写。差异性必须沿“模板数据→编译策略→同一经历的选择/遗忘→自省/知识/意图→可解释观测”验证。

| 路径 | 收益与成本 | 决定 |
| --- | --- | --- |
| 原架构内闭环全部核心，保留file依赖与配套环境 | 能保持领域/mesh边界；需先解决上游能力证据、迁移和受控安装，维护成本中等 | **采用**；对应用户完整核心目标 |
| 主流程先行的小范围测试包 | 较快获得反馈，但缺回放/比较/隔离验收；投入较低，后续仍要补齐 | 可用于内部候选验证，不能作为此次最终发布完成 |
| 重写通讯层或替换mesh依赖 | 增加重复状态和兼容成本，违背B04与架构边界 | 排除；不是上游能力缺失的兜底方案 |

不把39项缺口等同于39个等量任务。本计划归并为 **16个工作包WP00–WP15**，每个R项只有一个主关闭工作包；跨包集成由公共契约和发布门槛复核。

## 待讨论问题的落地口径

以下为本计划选择的工程默认方案，与B/Q用户决策区分。实现阶段若发现证据使其不可行，应给出冲突及替代方案，不静默换口径。

| 编号 | 计划采用的方案 | 必须验证的边界 |
| --- | --- | --- |
| E01 虚拟时间 | 新写入以**整数虚拟分钟**为计算基准，接受旧`W3D1T14`并扩展`W3D1T14:30`；保留旧周/日原点，新分钟值由旧小时值乘60无损派生；旧文本不强行改写 | 禁止浮点小时生成非法字面量；分钟累计、跨日/周、倒退、旧格式恢复一致；来源事件时间与整理时刻分开 |
| E02 轮次与预算 | 场景持久化总轮数上限；run.maxTurns只限制本次最多完成的轮数，不重置总上限；实际返回区分本次/累计。用量按真实会话事件记账，达到软限停止新cue，在途完成后硬停 | token预算不是“发cue次数”；非已知消费不得标consumed；真实生成可能超出剩余额度，明确记录实际超额且不得再调度新轮，不承诺能事后截断已发生用量 |
| E03 关闭与超时 | 将“停止新发送/收敛/结束自省/解散/完成检查”显式分阶段。收敛及压缩等待各暂定可配置30秒真实时间，有界并可注入时钟测试 | 超时返回未完成/降级证据，不伪造成功；重启可续。压缩超时放行必须记录可追溯失败和已保存的合法提炼意图，不复制整份mesh历史 |
| E04 自省深度 | 自动触发无待处理输入则skip；少量低唤醒输入light；阈值来自MemoryPolicy（验收fixture固定3条/0.6），scene_end有输入时full；pre_compaction有待提炼范围必full；手动可显式请求full | light不改L2，完成后留记录；同一逻辑批次按既定触发优先级合并，mesh负责执行串行，角色层只做关联和幂等 |
| E05 短摘录 | quote默认最多80个Unicode码点，detail最多400；限制只对新写入生效。超限返回结构化参数错误，要求工具重试，不静默截断引文；P2不得保存未见原文 | 中文、组合字符、空值及超限行为清楚；旧超长数据保留并报告，展示仍受预算限制；数值是本计划默认，不冒充原设计硬指标 |
| E06 pending_taught | 在owner的agent_state专用版本化键保存有界待定索引，包含讲者情节、听者、topic、原时刻和状态；完成/拒绝留state_writes，知识事件补不可变教学归因 | 听者后续事件验证成功才迁移；证据不足保持pending，不因超时自动mastered；重复日终一次生效，越界查询只在受控服务执行 |
| E07 队列与日终 | learningQueue仍以**最近完成自省记录的完整output快照**为读取依据；每次包含保留旧项、入队/触及/降档时刻和revision。无LLM的日终用light完成记录保存新快照，不覆盖旧快照 | 无新提议不清空旧队列；误区优先、三日降档、同优先淘汰最旧；agent_state仅存日终阶段检查点/幂等键，不建立第二个当前队列权威 |
| E08 旧实例绑定 | 初次迁移需显式核对旧角色库与mesh实例；优先使用上游可证明的稳定实例标识，不以路径hash或可随意复制的sidecar冒充数据库身份 | 若现有mesh没有可证明的身份/配对能力，WP00阻断该方案及最终发布；不修改上游数据库、代码或依赖来绕过。旧NULL不自动当正确 |
| E09 模型来源 | 用规范化、无凭据的实际配置hash，写入情节/自省/检索历史；保存可解析的版本化配置快照。setModelConfig独立于respec，在安全evict/warm边界生效 | 主/自省独立模型可追；换模不改旧hash。旧NULL来源标unknown，不能用当前配置回填伪历史；旧记录回放降低fidelity |
| E10 保守迁移 | 不自动激活不兼容角色，不自动改变不可变身份；parse失败、无法证明owner/模型/时间的数据进入兼容报告并禁止相关写路径，保留原数据 | “迁移成功”细分为结构升级、数据保留、可运行兼容三种结果，不把归档保留说成行为兼容 |
| E11 受控发布 | 0.1.0候选用制品编号/提交hash区分，不反复向同一registry发布同版本；不创建1.0.0或预发布语义版本来代替当前要求 | 最终包与被验收包校验和一致；目标0.1.0已占用则停止，不覆盖、不擅改版本 |

## 数据与接口冻结契约

### 数据迁移范围

保持**14领域表与双库分离**，不增加角色会话镜像、mesh表或跨库ATTACH。拟新增`migrations/002_release_closure.sql`并将`SCHEMA_VERSION`从1升2；npm版本仍为0.1.0。若执行前已有新迁移，应重新编号而非覆盖。001保留不改。

| 编号 | 数据落点 | 计划变化及唯一权威 |
| --- | --- | --- |
| S01 | agents、agent_specs | agents新增版本化注册意图/阶段，成功注册投影与“打算注册”分开；新增兼容状态。agent_specs支持不可变revision与文件指纹历史，重建索引/约束时保留旧行，不仅覆盖最新快照 |
| S02 | scenes | 增加分钟时钟、轮次/关闭阶段、稳定cue关联键与进度；仅存领域调度意图和mesh引用，不存mesh投递副本；一场景一conversation关系不变 |
| S03 | episodes、knowledge_items、knowledge_events | 增加分钟投影；知识保留衰减前掌握度及事件级taught归因，补来源/用途一致性；model_config_hash保持历史含义 |
| S04 | reflections | 增加depth、触发幂等键/批次、完成游标与可恢复状态；input/output为不可变批次快照，关联先持久化再发送，避免快速结果先于inFlight登记 |
| S05 | agent_state、state_writes | 强类型、带schemaVersion的pending教学、日终检查点、设施状态/模型配置快照键；每类键指定唯一写入服务，禁做无约束杂物存储；所有状态迁移留审计 |
| S06 | retrieval_log | 增加教学进度用量、预算版本/层用量、来源/调用ID；区分auto与explicit recall，调整原(owner,trigger)唯一键以容纳显式多次回忆但保持自动幂等；空结果也留快照 |
| S07 | boundary_events、memory_decisions、subject_profiles | 补事件归因/幂等和健康告警类型、消费判定阶段、画像依据；区分上游reject码与本地健康码，不能把任意新码混进旧reject集合 |

WP01给出字段/索引/JSON schema冻结清单，WP02实现同一批迁移；后续工作包不得分别偷偷补表或临时改列。长历史的spec/model快照不含密钥，不复制整份会话原文。新库与旧库升级后应产生同一目标schema及有效FTS，不用行数相同代替业务数据核对。

**副本迁移流程：** 停止所有写者并关闭连接 → 对角色库、配对mesh库、实例模板及会话资料制作一致性备份/副本清单 → 在副本预检、迁移角色库 → 校验行级主键/owner/引用/FTS/模型未知标记与禁止激活清单 → 用原版及候选版分别验证其允许的副本 → 显式切换新环境。不得只复制打开中的SQLite主文件而遗漏WAL。

回退只切回完整旧版本与其配套快照；旧程序不得打开新版schema。切换后若已有新写入，先停止并保留增量及审计，单独决定前向修复/数据协调，不能直接覆盖为旧备份。普通迁移不得写mesh库；必要的注册修复仍通过mesh公开API，单独审计。

### 公共接口冻结清单

仅`src/index.ts`导出工厂、公开类型和错误；不泄露mesh/registry/数据库句柄。下列是待实现/冻结的能力清单，最终方法名在WP01保持邻近命名风格后固定。

- `agents`：create、createBatch、reconcileRegistrations、setModelConfig、respec、身份一致性报告、可恢复退役/删除语义。batch按项返回状态，不承诺跨库整批原子回滚；身份不可变规则不适用于合法的独立模型更新。
- `memory`：宿主只读查询/统计明确owner与管理视图；模型工具remember/recall/note_self与宿主查询分开，查询不得隐式强化/降置信。
- `scenes`：create/run/resume/close明确状态机、总量/本次量、收敛超时、AbortSignal；不把O04/O05的pause/inject偷偷加入此次范围。
- `reflect`：触发/读取/结果状态包含reflectionId、完成与失败语义；已发送不等于成功，重复调用关联不靠账号单一易失变量。
- `facilities`与`blueprints`：现有兼容schema共享；设施落库/工具/应答/恢复，蓝本保持AuthorModel注入与显式promote。
- `inspect`：不变量、可见性时间线、印象演化、成本、回放、比较；有副作用的悬挂修复与只读检查明确区分。回放包含fidelity/证据降级，不等于重新生成相同模型回答。
- 错误/结果：结构性错误、证据不足、旧数据不兼容、上游不支持、运行中/已完成、未知统计量分别表达，不用0/null/成功混淆。兼容变更逐条写入迁移说明。

## 角色差异性专项验收

差异性不是“让三名角色说话风格不同”而已，也不是强行让所有输入产生不同结果。**先验证相同模型/相同经历下的模板机制，再验证真实会话中该机制可达。** 所有fixture在WP01冻结，不得看到候选输出后调整预期以追求通过。

统一控制：同模型/版本/采样配置、同消息与顺序、同初始关系和虚拟时间；只改变要测试的模板字段。另设同模板重放对照、交换模板对照、未知第四角色对照。保存模板/spec/model hash、memory_decisions分量、选中ID、retention、画像delta、知识事件、队列revision和预算快照；不保存认证材料。

| 用例 | 控制与执行 | 必须成立的断言 |
| --- | --- | --- |
| DIF01 编译差异 | 至少三个匿名模板分别突出尽责性、新奇偏好、负面情绪敏感度；编译fixture包含0.2/0.8等明确参数，角色名称随意交换 | 政策字段按已定映射变化；缺字段保持中性；交换模板后结果随模板而不是名字变化；非法值在共享schema拒绝，不悄悄改成中性 |
| DIF02 同经历选择 | 为一组固定候选事件构造阈值内/阈值外/恰在阈值的输入；独立手算/参考公式给预期，不用同一个被测函数自产expected | 不同模板至少有预先指定的一条事件作出不同write判定；同模板重放完全相同；每次决定都能对应六路分量与threshold，不用模型措辞判断 |
| DIF03 遗忘与失真 | 同初始salience的中性/负面情节在0/24/72虚拟小时及0.70/0.45边界检查；情绪字段经实际工具写入 | 预设负面敏感/细节保留差异沿写入→衰减→卡片呈现贯通；比较仅对指定不饱和fixture要求单调，原始quote/detail不被改写 |
| DIF04 信任与自省 | 给相同证据、不同growth_rules/初始信任，执行一次合法及一次缺证据结果；包含同主体多条delta | 差异按模板速率产生且仍受统一硬限幅；缺owner证据不变更；同一reflection重复提交不重复生效；观测能解释原因 |
| DIF05 知识与主动意图 | 同topic设已掌握/薄弱/误区初态；经历相同教学，先讲者后听者，再跨入睡眠日终 | 知识迁移遵循证据而非角色标签；pending只能在双证据齐全后成立；误区high保留、三日未触及降档；模型实际输入包含该owner的意图 |
| DIF06 跨场景教学进度 | 用通用用途标记启用课程进度，构造两班两课、近期5条知识主体和consolidated进度 | 当前场景至多3条/200token，准确过滤班级/课程；重复集合可确定检出并呈现次数；基础/额外用量分账，总额≤2950 |
| DIF07 未知第四角色 | 不改源码，加入此前未出现角色名/蓝本，经历创建、场景、记忆、自省和恢复 | 不出现“未支持角色”分支；权限、owner、工具及预算一样有效。审查通用注册逻辑，不用简单关键词零命中取代实际行为验证 |
| DIF08 包外真实闭环 | 从候选包与配套mesh环境，只经公开入口运行上述样例；包含重启和一次模型配置切换 | 模板/策略/自省输入确实到达真实SDK；工具提交、知识/记忆/成本来源贯通，历史模型hash不变；不借内部mesh句柄救场 |

确定性DIF01–DIF07为硬门槛：预先冻结的断言全部通过、跨owner泄露为0、未经证据的掌握升级为0、重复副作用为0。名称相同而输入不同可以不同，模板不同也允许在饱和边界得到相同结果，不能把“差异越大越好”当标准。

真实模型验收不保证逐字复现或每轮必提问。WP00登记一个获准模型组合、花费上限与评估人；WP01冻结至少3个场景×3种模板×3次运行的样本设计，DIF08和第四角色冒烟另外登记。先看硬链路与权限/预算，再按“角色约束一致、差异可解释、知识/意图有连续性”的统一rubric记录通过/失败和样本。机制已证实但业务表现不足也不得伪称达标；候选评审须解释异常并明确通过或退回，禁止事后只挑成功样本或改阈值。凭据/经费未批准则标未执行并阻断最终发布，不在本轮调用真实模型。

## 保留file依赖的私有npm发布流程

B04是硬边界。**发布到registry不自动意味着可在任意目录执行一次普通npm install后使用。** 本版对外承诺“私有制品分发 + 已验收的配套目录安装环境”，不能宣称脱离同级mesh独立运行。

1. **先证安装路径，再写发布说明。** WP00用待执行实验比较：目标npm从registry/tgz安装时的file路径解析，以及从registry取得并校验tgz、解包到与mesh并列的`pi-agent-role`目录后由宿主本地接入的路径。只把实际通过的路径列为支持，不预设npm总按用户仓库根解析。
2. **配套材料显式提供。** 接收者须有获准版本的`pi-agent-mesh`目录及可用包产物；记录commit/包版本/构建指纹与相对目录布局，不读取或修改上游来冒充就绪。若现有受控环境不满足，给明确预检失败，不自动安装替代registry包。
3. **依赖字符串原样保留。** 打包前后检查`file:../pi-agent-mesh`完全一致，禁止改写发布manifest、override、vendor内嵌或把mesh打进包来暗中移除同级要求。Node/npm版本、受支持宿主布局写入安装契约。
4. **候选打包不是发布。** 构建后检查tarball清单及ESM/CJS/DTS出口，迁移文件能从包根定位；目标`files`允许清单、README、许可证及示例按需完善，排除凭据、用户库、会话、私有配置和无关开发文件。Sourcemap披露内容要审查。
5. **新环境消费验证。** 在受控空环境仅放候选包、批准的mesh配套目录及依赖，不借本仓库src、开发缓存或本机隐式认证。按支持路径测试JS ESM、CJS和TypeScript类型、native SQLite、初建/迁移/关闭/恢复；两平台分别运行。不是“完全无配套依赖”。
6. **首次正式发布。** 不提前向目标registry写入0.1.0试验包；候选保存在制品库。发布前复核registry地址/scope、0.1.0未占用、权限与安全凭据注入，再由获准发布者执行。当前license字段为MIT，但不能据此省略实际许可证文件与依赖许可证检查。
7. **同版本不可反复覆盖。** 若发布失败须先查询远端状态，不能盲重试或假定未写入；如果0.1.0已存在，不覆盖、不清除历史、不改版本。后续版本或内部修订策略须重新确认。
8. **发布与数据回退分开。** 发现缺陷先停止推广候选/切回受支持旧部署及其兼容数据快照，保留新写入；私有registry侧的弃用/标签调整须按权限另行批准，不将包回退等同于数据库降级。

registry URL、发布者和凭据不写入本计划；WP00只登记非敏感环境标识、批准记录及证据位置。scope是否允许私有访问由目标registry实际规则决定，不把公开npm的权限选项直接套用。

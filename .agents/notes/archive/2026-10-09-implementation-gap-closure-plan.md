## 结论与计数口径

**不是“只剩 P7”。** 当前已有角色运行时骨架及大量算法、DAO、门面和测试，但一些已勾选任务尚未完成真实会话、跨模块接线或故障恢复闭环。

本次从文档需求映射到源码与测试，按可验收的工作单元去重，形成以下后续计划：

| 类别 | 数量 | 口径 |
| --- | ---: | --- |
| 必需闭环任务 R01–R39 | **39** | 其中 **7 项未见目标功能实现、32 项部分实现**；均未启动本计划中的实施工作 |
| 可选增强 O01–O07 | **7** | 与基础交付分开，不全部套用旧 P7 的上游阻塞标签 |
| 文档校准 D01–D02 | **2** | 不作为软件功能缺失，不与 R 项重复计数 |
| 上游能力核验 U01–U03 | **3** | 解除不确定性的核验关卡，不是额外 3 个产品功能；与 R/O 项存在依赖关系，不相加 |
| 用户已确认的规则 Q01–Q10 | **10** | 本轮完成规则确认；未修改旧设计、权限设置或实现 |

**本计划共列 48 个后续工作单元（39 必需 + 7 可选 + 2 文档），另有 3 个上游核验关卡。** 这不是 48 个独立 bug，也不是 48 个等量工时的任务。R 项按可共同验收的目标归并，算法、接线、故障和测试缺口可能属于同一项。

旧任务清单有 **51 个 `[x]`、2 个 `[ ]`**；这仅是文档标记，不能解释为已完成 51/53。旧 rollout 仍把阶段写成 `todo`，同样不能解释为代码未做。本次不计算全项目完成率：旧条目粒度不一致，且未运行测试、真实模型或上游联调。

## 目标与本轮边界

本计划的目标是把“有代码/有测试文件”推进为“公开入口可达、跨模块语义一致、失败后可恢复、验收证据可复查”。

本轮仅完成：

- 核对 `plan`、`review`、`tech` 的当前快照，并追踪相关源码与测试。
- 确认设计冲突的取舍，形成依赖、验收标准与工作清单。
- 只新增本文件；**不实施、不修代码、不修改既有文档，不安装依赖，不运行测试或构建，不提交 Git**。

后续任何实现、迁移、权限收紧、CI 配置修改或真实模型验收，均需另行启动任务。本文件中的“验收”描述的是未来工作，不是本轮已通过的测试。
